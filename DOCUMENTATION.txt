================================================================================
                    WINNIE DA POOH - DOCUMENTATION
================================================================================

Winnie Da Pooh is a reproducible forecasting data pipeline and benchmarking 
framework. It normalizes data from prediction markets (Kalshi) and forecasting 
platforms (Metaculus) into a unified format for testing forecasting models.

--------------------------------------------------------------------------------
1. QUICK START / USAGE
--------------------------------------------------------------------------------

Prerequisites: Python 3.13+, `uv` (package manager).

**Installing `uv`** (if not already installed):
- **macOS/Linux**: `curl -LsSf https://astral.sh/uv/install.sh | sh`
- **Windows (PowerShell)**: `powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"`
- **Alternative**: `pip install uv` or `brew install uv`

**After installation**, add `uv` to your PATH:
- Run: `source $HOME/.local/bin/env` (or restart your terminal)
- Verify: `uv --version`

| Step | Command | Description |
|------|---------|-------------|
| 1 | `uv sync` or `uv sync --all-groups` | Install dependencies. Use `--all-groups` to include dev dependencies (pytest, etc.). |
| 2 | `cp .env.example .env` | **Initial setup only**: Configure API keys (Kalshi/Metaculus). Skip if you already have a `.env` file or if `.env.example` is missing. |
| 3 | `uv run scripts/build_db.py --start 2023-01-01 --end 2025-12-31` | Fetch data from Kalshi's public S3 bucket and build dataset. |
| 4 | `uv run runner/runner.py --method mlp_nn` | Run a benchmarking experiment. |
| 5 | `uv run scripts/inspect_parquet.py` | View summary statistics of the latest dataset. |
| 6 | `uv run python tests/parquet_quality.py --parquet data/datasets/<folder>/data.parquet` | Run comprehensive data quality audit (validates 15 requirements, ~2-3 min). |

**Troubleshooting `uv sync`**:
- If `uv: command not found`: Install `uv` using the commands above
- If sync fails: Try `uv sync --all-groups` (includes dev dependencies)
- Alternative: `uv pip install -e .` (if `uv sync` doesn't work)
- Ensure `uv.lock` file exists and is up to date

**Kalshi API enrichment tuning**:
- Use `--kalshi-batch-size` with `scripts/build_db.py` to control the /markets batch size.
- Example: `uv run scripts/build_db.py --start 2024-12-30 --end 2024-12-31 --kalshi-batch-size 70`

**Environment Variables (`.env`)**:
- `KALSHI_API_KEY_ID`: Your Kalshi API key UUID.
- `KALSHI_PRIVATE_KEY_PATH`: Path to your `.pem` private key file (e.g., `kalshi_key.pem`).
- `METACULUS_TOKEN_1`, `METACULUS_TOKEN_2`, ...: One or more Metaculus API tokens for rotation.
- `METACULUS_TOKEN`: (Legacy/Single) Fallback Metaculus token.

--------------------------------------------------------------------------------
2. DATA SCHEMA
--------------------------------------------------------------------------------

The pipeline normalizes data into two primary structures, stored in a unified 
Parquet format.

A. EventRecord (The "Static" Info)
Defined in `src/common/schema.py`.

| Field | Type | Description |
|-------|------|-------------|
| source| str | "kalshi" or "metaculus" |
|event_id| str| Unique event ID within the source. |
| title  | str | Event name. |
| description | str | Full context of the event. |
| url | str | Link to the original platform. |
| market_type | Enum | event. |
| options_json| str (JSON) | List of option objects (one per market/answer). |
| end_time | datetime | When the event closes (max over options). |
| status | Enum | open, closed, resolved, or unknown. |
| resolved_value_json| str (JSON) | Resolved option_id if uniquely resolved. |
| metadata_json | str (JSON) | Event-level metadata (derived). |

B. Option TimeSeries (The "Belief" History)
Stored inside `options_json` as per-option lists.

| Field | Type | Description |
|-------|------|-------------|
| ts | datetime (ISO string) | Timestamp of the prediction/trade. |
| belief | float | The normalized probability or price (0-1). |
| volume | float | Trading volume (Kalshi-specific). |
| open_interest | float | Active contracts (Kalshi-specific). |
| bid / ask | float | Best buy/sell prices (Kalshi-specific). Optional, ~81% coverage. |

**Note on bid/ask**: Sourced from `/markets/candlesticks` (daily OHLC). Null for: 
synthetic options (no orderbook), zero-volume markets, ultra-short-lived daily markets.

--------------------------------------------------------------------------------
3. CORE CLASSES & MODULES
--------------------------------------------------------------------------------

A. Data Handling (`dataobject/`)
- `EventDataset`: Entry point for loading `.parquet` data.
- `EventRecordWrapper`: Helper to access row data with validation.
- `SplitManager`: Handles reproducible Train/Test/Bench splits via hashing on `event_id`.

B. Task Definitions (`dataobject/tasks/`)
- `Task`: Abstract base class for defining prediction problems.
- `ResolveEvent`: Multiclass resolution task over event options.
- `Example`: A single data point (features + option histories + target distribution).
- `Batch`: A collection of `Example` objects.

C. Forecasting Methods (`methods/`)
- `ForecastMethod`: Base class for all models/baselines. Supports `.fit()`, `.predict()`, `.save()`, `.load()`.
- `LastPriceBaseline`: Simple baseline that predicts the most recent belief.
- `MLPForecaster`: A simple Neural Network (MLP) trained on price history.
- `registry.py`: Central factory for instantiating methods.

D. Experiment Workflow (`runner/`)
- `RunSpec`: Serializable configuration for an experiment run.
- `runner.py`: The primary CLI for orchestrating data loading, training, and evaluation.
- `evaluator.py`: Computes metrics (multiclass Brier, LogLoss, etc.) per task.

--------------------------------------------------------------------------------
4. HOW TO BUILD OFF THIS REPO (Best Practices)
--------------------------------------------------------------------------------

A. Adding a New Forecasting Method
1. **Create**: New file in `methods/` (e.g., `methods/my_model.py`).
2. **Subclass**: Inherit from `ForecastMethod`.
3. **Implement**:
   - `.fit(train_batches, spec)`: Logic to train your model.
   - `.predict(batch, spec)`: Return a list of per-option probability distributions.
   - `.save(path)` / `.load(path)`: (Optional) Handle persistence.
4. **Register**: Add your class to `METHODS` in `methods/registry.py`.

B. Adding a New Task
1. **Create**: New file in `dataobject/tasks/` (e.g., `dataobject/tasks/my_task.py`).
2. **Subclass**: Inherit from `Task`.
3. **Implement**:
   - `.make_examples(record, rng)`: Define how to turn an `EventRecord` into `Example` objects.
   - `.metric_fns()`: Return a dict of `{name: sklearn_metric_fn}`.
4. **Register**: Add it to `TASK_REGISTRY` in `runner/runner.py`.

C. Experiment Artifacts
All outputs are stored in `data/outputs/` (ignored by git). See `runner/results_db.py` for detailed output structure and indexing logic.
